#Design Memo

#A stack is the right choice for an undo/redo system because actions need to be handled in last-in, first-out order. The most recent action should be the first one that is undone. When an action is undone, it is removed from the undo stack and placed on the redo stack. If the user chooses redo, the most recently undone action is removed from the redo stack and returned to the undo stack. This behavior matches how stacks are designed to operate.

#A queue is better suited for a help desk because customers should be helped in the exact order they arrive. A queue follows a first-in, first-out structure. The customer who enters first is at the front and should be helped before customers who arrive later. The enqueue method adds customers to the rear, while dequeue removes customers from the front. The peek method allows the help desk to see who is next without removing that customer.

#These implementations differ from Python's built-in lists because they use custom Node objects and pointers rather than relying on list methods such as append() and pop(). The Stack class tracks a top pointer, while the Queue class tracks both front and rear pointers. Building these structures manually demonstrates how data is connected and how operations such as push, pop, enqueue, and dequeue work internally.
